# 로컬 전용 Kafka Studio

## 사용 방법

1. Finder에서 프로젝트 폴더의 **Kafka Studio.app**을 더블클릭한다.
2. 준비가 끝나면 기본 브라우저에 `http://127.0.0.1:4318`이 열린다.
3. Kafka가 실행 중이면 자동으로 연결된다. 꺼져 있으면 웹 상단의 **Kafka 시작**을 누른다.
4. Producer·Consumer 시작, 메시지 전송, 토픽 관리는 기존 웹 화면에서 진행한다.

터미널을 직접 열거나 토큰을 복사할 필요가 없다. 시작 과정에서 웹을 빌드하므로 처음 열 때 잠시 기다린다. 의존성이 없으면 `npm ci`로 설치하므로 최초 준비에는 인터넷이 필요할 수 있다. 이미 실행 중인 Studio는 새 서버를 만들지 않고 재사용한다. 코드 수정 후에는 Studio를 종료하고 다시 열어야 새 빌드가 적용된다.

앱은 프로젝트 파일을 함께 사용한다. **Kafka Studio.app만 다른 폴더로 옮기지 않는다.** 바탕화면에서 쓰려면 Finder에서 이 앱의 가상본을 만들어 옮긴다. 프로젝트 폴더 전체 이동은 가능하다.

## 웹 상단 버튼

- **상태 새로고침**: Docker 연결 및 지정 Kafka 컨테이너의 상태를 확인한다.
- **Docker 환경 시작 · Colima**: 설치된 Colima를 시작한다. Docker Desktop 사용자는 Docker Desktop 앱을 실행한다.
- **Kafka 시작**: 기존 `ksl-kafka` 컨테이너를 시작한다. 컨테이너를 새로 만들거나 이미지를 다운로드하지 않는다.
- **Kafka 연결 · 다시 연결**: 실제 Kafka에 재연결한다. 컨테이너 시작 직후 브로커 준비가 늦으면 잠시 후 누른다.
- **모의 모드**: 현재 웹 연결의 CLI 세션을 정리하고 모의 실습으로 전환한다.
- **중지 및 종료 → Kafka 중지**: 대상 확인을 체크한 후 Kafka를 중지한다. 통합 서버에 연결된 모든 실습 CLI를 먼저 정리한다. 같은 Kafka를 사용하는 다른 앱도 영향을 받는다.
- **중지 및 종료 → Studio 종료 · Kafka 유지**: 실습 CLI와 통합 서버를 종료한다. Kafka와 Docker는 유지한다.

브라우저 탭만 닫으면 해당 실습 세션은 정리되지만 통합 서버는 계속 실행된다. 완전히 종료하려면 웹의 Studio 종료 버튼을 사용한다. 다른 탭에서 실행 중인 Studio 실습 세션도 함께 종료된다.

## 기존 실습 가져오기

기존 개발 화면(5173)과 새 로컬 화면(4318)은 브라우저 저장 공간이 다르다. 기존 화면에서 JSON으로 내보낸 뒤 새 화면에서 가져온다. 새로 가져온 토픽 정의와 세션 설정은 자동으로 실행하지 않는다.

## 준비 조건 및 범위

현재 Mac 환경의 Node.js 22.18 이상, Docker/Colima, 기존 `ksl-kafka` 컨테이너와 `apache/kafka:4.0.0` 이미지를 사용한다. Node 실행 경로는 `/usr/local/bin`, `/opt/homebrew/bin` 등을 확인한다. nvm만 사용하는 환경은 Node 경로를 별도로 구성해야 한다. 이 앱은 개발 폴더용 macOS 실행기이며 Node나 Docker를 포함한 배포용 설치 패키지는 아니다.

통합 모드는 Docker용이다. 로컬 Java/Kafka 설치 모드와 기존 수동 연결 방식은 `local-agent/README.md`를 참고한다. 컨테이너 이름·이미지·bootstrap 환경 변수는 기존 `KAFKA_CONTAINER`, `KAFKA_CLI_IMAGE`, `KAFKA_BOOTSTRAP_SERVER`를 따른다. Finder 실행의 기본값은 현재 프로젝트 환경에 맞춰져 있다.

## 문제 확인

실행 실패 시 `local-agent/.local/실행 오류.txt`를 열어 안내한다. 자세한 준비/서버 로그는 `local-agent/.local/launcher.log`에 있다. 4318 포트를 다른 프로그램이 사용 중이면 해당 충돌을 해결해야 한다. 실행기는 다른 프로그램을 강제 종료하지 않는다.

주소만 직접 열어 인증 오류가 나면 **Kafka Studio.app을 다시 연다**. 서버 재시작 후에도 동일하다. macOS가 실행을 차단하면 표시된 이유를 확인해야 한다. 시스템 보안 설정을 자동 변경하지 않는다.

## 구현과 검증

통합 서버는 loopback에만 바인딩하고 웹 파일 및 인증된 Kafka API 프록시를 제공한다. 내부 agent도 임의 loopback 포트를 사용한다. 실행기는 파일 권한으로 보호된 로컬 상태를 읽고 30초짜리 일회성 티켓을 발급받는다. 티켓은 HttpOnly·SameSite=Strict 세션 쿠키로 교환한 뒤 URL에서 제거한다. Kafka 제어는 정확한 Origin과 쿠키 인증을 요구하며, 입력받은 셸 문자열을 실행하는 API는 없다. 인증 상태 파일은 Git에서 제외된다.

검증: 웹/서버 테스트 총 24개, 빌드·린트·타입 검사, 실행기 진입점의 서버 시작, 쿠키 인증을 통한 실제 Kafka 한글 송수신, 브라우저 자동 연결과 Studio 종료를 확인했다. Kafka 시작/중지는 고정 인자와 세션 정리를 테스트로 검증했다. 현재 다른 실습도 사용하는 브로커는 실제로 중지하지 않았다. Colima의 꺼진 상태부터 시작 및 Finder 더블클릭의 화면 자동화 검증은 수행하지 못했다(네이티브 화면 도구 응답 실패).
