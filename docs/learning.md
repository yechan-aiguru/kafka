# 실습 가이드

## 설정 저장과 이전

왼쪽에 실습 이름을 입력하고 **현재 실습 저장**을 누른다. 같은 이름은 **덮어쓰기 허용**을 켠 경우에만 교체한다. 저장된 실습을 선택해 불러오거나 삭제할 수 있다. 마지막 저장/불러온 설정은 새로고침 후 복원되며, 미저장 변경은 복원하지 않는다.

저장 대상은 이름·Topic 정의·세션 인자·Bootstrap server다. 토큰, 연결 ID, 실제 프로세스, 메시지, 터미널 기록은 저장하지 않는다. `schemaVersion: 1` JSON만 지원하며, 임의 인증 필드는 검증 과정에서 제거한다. JSON 가져오기는 256KB, 세션 8개, 토픽 100개까지 허용한다.

불러오기는 현재 웹 세션을 중지하고 설정만 복원한다. **불러온 토픽 정의**를 확인한 다음 **없는 토픽 생성**을 따로 눌러야 한다. 기존 토픽은 자동 변경하지 않는다. 토픽 생성 중 일부가 실패하면 이미 생성된 토픽은 유지되므로 목록을 새로고침하고 다시 준비한다. 세션도 직접 시작해야 한다.

브라우저 저장 공간이 부족하거나 사용이 차단되면 오류를 표시한다. 다른 주소/브라우저로 이동하려면 JSON 내보내기와 가져오기를 사용한다. 저장 삭제는 현재 실습 화면이나 Kafka 토픽을 삭제하지 않는다.

## 세 가지 템플릿

- 단일 Producer/Consumer: 한 건 송수신부터 시작한다.
- 같은 그룹의 Consumer 2개: 파티션을 분담한다.
- 서로 다른 그룹의 Consumer 2개: 두 그룹이 각각 메시지를 읽는다.

템플릿의 기본 토픽은 `orders`다. 실제 연결에서도 토픽 준비 버튼 또는 토픽 관리에서 명시적으로 생성한 후 시작한다.

## Producer 파티션 선택

인자 설정의 **Producer 파티션 선택**은 메시지가 들어갈 파티션을 정한다.

- 기본 + key:value 활성화: key의 UTF-8 Murmur2 해시로 파티션을 선택한다.
- 기본 + key 없음: 실제 Kafka 클라이언트의 기본 분배를 사용한다.
- Round Robin: Kafka의 `RoundRobinPartitioner`를 사용하며 key를 분배 기준으로 쓰지 않는다. 실제 구현은 배치 등으로 단순한 0→1→2 순서와 달라질 수 있다.

반복 전송의 템플릿을 `customer-1:message-{n}`으로 설정하고 10건을 보낸다. Consumer 출력의 Partition·Offset·Key를 비교한다. 토픽 파티션을 늘리고 같은 key를 다시 전송해 새 메시지의 목적지를 비교한다. 기존 메시지는 옮겨지지 않으며 모든 key의 목적지가 반드시 변하는 것은 아니다.

배치는 1~100건, 간격 0~5000ms다. 전송 취소/세션 중지/화면 종료로 중단한다. 완료 숫자는 stdin 전송 요청 수이며 broker 저장 보장 횟수가 아니다. 실제 전달은 Consumer 수신 및 Lag 조회로 확인한다.

## Consumer 할당과 리밸런싱

인자 설정의 **Consumer 할당 전략**은 파티션을 그룹 멤버에게 배정하는 방식이다. Kafka 4.0의 `classic` 프로토콜을 명시하며 Range 또는 Round Robin을 제공한다. 같은 그룹은 같은 전략을 선택한다. 현재 한 Consumer는 한 토픽만 구독한다.

1. Consumer 하나를 시작하고 그룹 패널에서 해당 Group을 조회한다.
2. 같은 그룹 Consumer를 추가·시작한다.
3. 할당이 안정된 뒤 다시 조회한다. 이전/현재 Consumer를 표에서 비교한다.
4. 하나를 중지하고 다시 조회해 재할당을 비교한다.

조회는 수동 스냅샷이다. 최신 조회와 바로 이전 조회를 비교하며 백그라운드 자동 모니터링은 하지 않는다. 동일 토픽·동일 구독에서는 전략별 파티션 개수가 같을 수 있다. 여러 토픽을 구독하는 assignor의 모든 경우를 모의 모델로 재현하지 않는다.

## Offset·Lag와 다시 읽기

표의 Committed는 다음에 읽을 저장 위치, Log end는 로그의 다음 위치, Lag는 그 차이다. 아직 commit이 없으면 `미커밋`으로 표시한다. 실제 Kafka는 auto commit 주기에 따라 값이 늦게 반영된다.

새 그룹 이름과 `--from-beginning`으로 시작하면 보관된 메시지를 처음부터 읽는다. 기존 그룹은 저장된 offset이 우선이므로 `--from-beginning`만으로 되감기지 않는다.

기존 그룹을 되감으려면 해당 그룹의 **모든** Consumer를 중지한다. 그룹 패널의 초기화 실험에서 Topic과 확인용 Group 이름을 입력한 뒤 실행한다. 서버가 Kafka의 그룹 상태를 확인하고 Empty/Dead 및 멤버 0일 때만 `--reset-offsets --to-earliest --execute`를 요청한다. Kafka도 실행 시 그룹 상태를 검사한다. 실행 후 그룹을 조회해 결과를 확인한다. 다른 앱에서 실행 중인 같은 그룹 Consumer도 중지되어야 한다.

## 모의 모드의 범위

모의 메시지는 토픽당 최대 10,000건이며 새로고침 시 사라진다. 파티션별 로그, Range/Round Robin 할당, 그룹별 읽기 위치와 재할당을 제공한다. commit은 즉시, 무키 기본 분배는 5건 단위 sticky로 단순화한다. 타이밍·리더 복제·장애·실제 클라이언트의 적응형 분배를 재현하지 않는다. 실제 동작의 증거는 로컬 Kafka 결과로 확인한다.

참고: [Kafka 4.0 기본 운영](https://kafka.apache.org/40/operations/basic-kafka-operations/), [소비자 설정](https://kafka.apache.org/40/configuration/consumer-configs/), [RoundRobinPartitioner](https://downloads.apache.org/kafka/4.0.1/javadoc/org/apache/kafka/clients/producer/RoundRobinPartitioner.html).

## 예외 상황 실습 패널 · 2026-09-30

세션 위의 **예외 상황 실습**을 열고 실습을 선택한다. **1. 실습 설정 적용**은 현재 세션을 중지하고 설정을 교체한다. **2. 전용 실습 토픽 생성**을 누른 후 각 세션을 시작한다. 매번 새 `kts-case-*` 토픽과 그룹을 사용하므로 기존 실습의 offset에 영향을 받지 않는다. 실제 토픽과 메시지는 자동 삭제하지 않는다. 설정은 기존 저장 기능으로 보관할 수 있지만 검사 결과·선택한 안내 패널은 저장하지 않는다.

| 실습 | 확인할 내용 |
|---|---|
| Consumer가 파티션보다 많을 때 | 파티션 1개와 Consumer 3개, 할당 없는 Consumer, 담당 Consumer 중지 후 재할당 |
| Consumer 중지·복구 | commit 확인 후 Consumer 중지, 추가 전송에 따른 Lag 증가, 같은 그룹 재시작 |
| from-beginning과 기존 offset | 기존 그룹 재시작과 새 그룹의 처음부터 읽기 비교 |
| 같은 key 편중·입력 오류 | 한 key의 파티션 집중, key:value 구분자 없는 입력 차단 |
| 파티션 증가 | 기존·새 메시지의 목적지 비교, 일부 key의 목적지 변화 |
| 잘못된 관리 요청 | 중복 토픽 생성, 파티션 감소, 브로커 수 초과 복제, 정지 Producer 전송 |

오류 검사 버튼은 실제 API를 호출한다. Kafka가 반환한 오류와 Studio가 CLI 호출 전에 차단한 오류를 구분한다. 중복 생성은 실제 환경에서 Kafka의 TopicExistsException을 확인하며, 파티션 감소·복제 수 초과·잘못된 입력·정지 세션 전송은 Studio의 검증 결과다. 전제조건 조회 실패는 일반 오류로 표시한다. 예상 패턴과 다른 오류는 **판정 보류**, 요청이 성공하면 **예상과 다른 성공**으로 표시한다. 연결 실패를 기대한 오류로 집계하지 않는다.

복제 수 초과 검사는 조회된 브로커 수 + 1을 사용하고 별도 `-rf-check` 토픽 이름을 사용한다. 검사 사이 클러스터 상태가 바뀌어 생성이 성공하면 그 결과를 표시하고 토픽을 남긴다. 자동 삭제하거나 성공을 오류로 꾸미지 않는다.

그룹 패널의 **이 화면의 Consumer별 조회 결과**는 설정된 세션과 마지막 조회의 client ID를 대응한다. 할당 없음은 유휴, 가입 대기, 정지 등 여러 이유일 수 있다. 프로세스가 실행 중이라고 그룹 가입 완료를 뜻하지 않으므로 리밸런싱 이후 재조회한다.

현재 지원하지 않는 자동 장애 실습: 여러 브로커의 리더 장애/ISR 축소, min.insync.replicas와 acks의 내구성 비교, 네트워크 지연·단절 주입, 트랜잭션·수동 commit 기반 중복 처리. 이러한 실습은 별도 격리 클러스터와 추가 클라이언트 제어가 필요하다. 현재 공유 중인 브로커를 자동으로 중단하지 않는다.

Kafka 동작 설명 참고: [Kafka 4.0 Consumer API](https://kafka.apache.org/40/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html), [Kafka 4.0 파티션·그룹 운영](https://kafka.apache.org/40/operations/basic-kafka-operations/).
