# 실습 환경 관리

`Kafka Studio.app`으로 연 로컬 화면 상단의 **실습 환경 설정**에서 관리한다. 정적 웹/모의 모드의 브로커 시뮬레이션 설정이 아니라 실제 Docker Kafka 환경이다.

1. 단일 브로커 또는 3개 브로커 프리셋을 선택한다.
2. 이름, 기본 파티션 수, 복제 수, 최소 ISR, 보존 시간, 자동 토픽 생성, 브로커당 메모리 한도를 입력한다.
3. **새 환경으로 저장**을 누른다.
4. **현재 환경**에서 저장한 환경을 선택하고 상단 **Kafka 시작**을 누른다.
5. 컨테이너가 시작된 뒤 브로커가 준비될 때까지 잠시 기다린다. 연결 실패 시 **Kafka 연결 · 다시 연결**을 누른다.
6. 사용 후 **중지 및 종료**에서 대상 이름을 확인하고 Kafka를 중지한다. Studio 종료만으로는 Kafka가 중지되지 않는다.

환경을 바꾸면 모든 Studio 탭의 CLI 세션이 정리된다. 이전 Kafka 환경은 계속 실행되므로 메모리가 부족하면 전환 전에 중지한다. 저장하지 않은 실습 설정은 전환 전에 시나리오로 저장한다. 환경 목록은 PC에 저장되며, 다른 탭에서 전환했다면 상태/환경 목록을 새로고침한다.

## 설정 범위

| 항목 | 범위 / 의미 |
| --- | --- |
| 브로커 | 1개 또는 3개, broker/controller 겸용 KRaft 학습 구성 |
| 기본 파티션 | 1~100 |
| 기본 복제 수 | 1~브로커 수 |
| 최소 ISR | 1~기본 복제 수; `acks=all`과 함께 비교 |
| 보존 시간 | 1~720시간; 세그먼트 정리 주기에 따라 삭제가 지연됨 |
| 자동 토픽 생성 | 기본 꺼짐 |
| 메모리 한도 | 브로커당 1/2/4 GiB; JVM heap은 절반 |

기본 파티션·복제 수는 자동 생성 토픽에 적용된다. 현재 토픽 생성 화면은 값을 명시하므로 그 입력이 우선한다. 3개 브로커·최소 ISR 2 환경에서 내구성을 실습하려면 **토픽 생성 화면에서도 복제 수 3**을 지정한다. 기존 토픽의 파티션·복제 수는 환경 저장으로 바뀌지 않는다.

저장한 설정은 고정한다. 바꾸려면 새 이름으로 저장해 다른 환경을 만든다. 실행 중인 클러스터의 quorum/브로커 수 변경은 지원하지 않는다. 환경은 최대 10개다. Kafka 버전은 `apache/kafka:4.0.0`으로 고정하며 해당 Docker 이미지가 미리 있어야 한다. 이미지가 없으면 최초 한 번 `docker pull apache/kafka:4.0.0`으로 준비한다. Docker 메모리 한도는 Colima/Docker 설정에서 조정한다. 각 컨테이너의 한도 합계 검사는 다른 컨테이너의 여유 메모리까지 보장하지 않는다.

## 격리와 저장

- 기존 `ksl-kafka`는 그대로 선택할 수 있다. 새 환경은 무작위 `kts-env-…` 이름의 전용 Docker 네트워크와 컨테이너를 사용한다.
- 외부 포트를 게시하지 않는다. Studio CLI는 선택한 첫 브로커의 네트워크 공간에서 `localhost:9092`에 연결한다.
- 환경 목록/선택은 `local-agent/.local/environments.json`에 원자적으로 저장된다. Git 및 시나리오 JSON 내보내기에 포함되지 않는다.
- 토픽과 메시지는 컨테이너 내부에 보존된다. 중지·재시작 및 Studio 종료에는 유지되지만 Docker 컨테이너 직접 삭제에는 복구되지 않는다. 자동 삭제 기능은 제공하지 않는다.
- 새 환경에서는 Studio 소유 라벨을 확인한 리소스만 시작/중지한다. 기존 Kafka는 실행기에 설정된 컨테이너를 제어한다. 일부 생성 실패 시 동일 환경에서 시작을 재시도하면 이미 만든 리소스를 재사용한다.

SSL/SASL, Kafka 버전 선택, 개별 브로커 장애 주입, 네트워크 지연, 실행 환경 삭제/기존 환경 직접 수정은 아직 지원하지 않는다.

## 검증

`local-agent/scripts/environments-integration.ts`는 임시 3개 브로커를 생성하여 브로커 등록, 6개 파티션·복제 수 3·ISR 3, 중지/재시작 후 토픽 보존을 검증한다. 테스트가 만든 컨테이너와 네트워크만 종료·제거하고 기존 Kafka는 변경하지 않는다.
