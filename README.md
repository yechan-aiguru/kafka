# Kafka Terminal Studio

Kafka 실습용 웹 터미널. Vite + React + TypeScript로 화면을 만들고, 실제 Kafka 쉘 실행은 사용자 PC의 작은 연결 서버가 담당한다.

실습 저장·JSON 이전·템플릿, 토픽/파티션 관리, Producer 분배 전략, Consumer 할당·리밸런싱 비교, Offset/Lag·초기화, 반복 전송까지 구현했다. 실제 Kafka 4.0.0 Docker 환경에서 검증했다. Vercel 정적 배포 설정은 준비했으며 공개 배포와 HTTPS → 로컬 연결 검증은 계정·배포 주소 연결 후 진행해야 한다.

## 로컬에서 간단히 실행

프로젝트 폴더의 **Kafka Studio.app**을 더블클릭한다. 웹 화면과 연결 서버가 함께 시작되고 브라우저가 열린다. Kafka가 실행 중이면 토큰 입력 없이 자동 연결한다. 꺼져 있으면 웹에서 Kafka 시작을 누른다. 사용 후 웹의 **Studio 종료 · Kafka 유지**로 종료한다.

[로컬 실행기 사용 방법](./docs/local-studio.md) — 준비 조건, 종료 정책, 기존 설정 이전, 오류 확인.

아래 npm 실행 방식은 개발하거나 수동으로 연결할 때 사용한다.

## 실행 구조

```text
web/                         local-agent/                  Kafka
브라우저의 실습 화면  ←→  사용자 PC의 연결 서버  ←→  CLI 프로세스·브로커
        │
        └─ 초기 UI 검증: 브라우저 내 모의 실행
```

Vercel에는 `web/`만 배포한다. 실제 Kafka를 사용할 때는 로컬 연결 서버와 Kafka가 별도로 실행되어 있어야 한다.

## 로컬 실행

Node.js 22.18.0 이상에서:

```sh
cd web
npm ci
npm run dev
```

양쪽 세션의 시작 버튼을 누른 뒤 Producer에서 메시지를 전송한다. 모의 실행은 단일 토픽의 Range/Round Robin 할당, key 해시, 즉시 commit을 단순화한 학습 모델이다. 실제 타이밍·장애·배치 기반 분배는 실제 Kafka에서 확인한다.

## 검증

```sh
cd web
npm run build
npm run lint
npm test
```

## 세션 사용법

- `세션 추가`로 새 Consumer를 만든 뒤 필요하면 역할을 Producer로 변경한다.
- `인자 설정`에서 세션 이름, 서버, 토픽과 역할별 옵션을 변경한다.
- 실행 중에는 옵션을 잠근다. 변경하려면 중지 후 다시 시작한다.
- 삭제는 실행 중인 세션을 먼저 중지한 뒤 화면과 이벤트 기록에서 제거한다.
- Producer 입력 후 Enter로 전송한다. key 사용 시 `order-1:hello` 형식으로 입력한다.
- `새 출력 따라가기`를 끄면 자동 스크롤 없이 이전 로그를 읽을 수 있다. 최근 이벤트는 세션별 200개까지 보관한다.
- 모의 모드의 기본 토픽은 `orders`, 실제 모드의 기본 실습 토픽은 `kts-practice`다. 임의 토픽 관리에서 생성·상세 조회·파티션 증가를 지원한다.

## 실제 Kafka 연결

1. 별도 터미널에서 `cd local-agent` 후 `npm run dev`를 실행한다.
2. `local-agent/.local/token` 파일을 읽어 웹 상단 연결 토큰 필드에 입력한다.
3. `실제 Kafka 연결`을 누르면 기존 토픽을 조회한다.
4. `토픽 관리 열기`에서 `kts-practice`가 없다면 해당 이름으로 생성하고 Consumer와 Producer를 시작한다.
5. Producer 입력창에서 Enter로 전송하고 Consumer 출력을 확인한다.

현재 환경의 기존 `ksl-kafka` / `apache/kafka:4.0.0`을 사용한다. 연결 서버는 127.0.0.1:4317, 웹은 127.0.0.1:5173이다. [설정·종료 정책·검증 방법](./local-agent/README.md)을 참고한다.

토큰은 서버 재시작마다 바뀐다. 페이지 새로고침/연결 해제 시 실습 프로세스는 종료하며 재연결 시 복원하지 않는다. OS 강제 종료 후 잔여 CLI 컨테이너 확인 방법도 연결 서버 문서에 정리했다.

## 예외 상황 실습

세션 위의 **예외 상황 실습** 패널에서 Consumer 과다, Lag 증가/복구, 기존 offset과 from-beginning, 같은 key 편중/잘못된 입력, 파티션 증가, 잘못된 관리 요청을 재현한다. 각 실습은 새 토픽·그룹 설정과 단계별 안내를 제공한다. 오류 검사 결과는 Kafka 응답과 Studio 사전 검증을 구분한다. [실습 가이드](./docs/learning.md)를 참고한다.

## 토픽·파티션 관리

- 왼쪽 `토픽 관리 열기`를 누른다.
- `브로커 조회`로 조회된 브로커 수와 ID를 확인한다.
- 새 이름, 파티션 수(1~100), 복제 수를 입력해 토픽을 생성한다. 실제 모드에서는 서버가 생성 직전 브로커 수를 다시 검증한다.
- `조회할 토픽`을 선택하면 각 파티션의 Leader, Replicas, ISR을 표시한다.
- `변경할 총 파티션 수`에는 추가량이 아닌 최종 개수를 입력한다. 현재 개수보다 크게만 적용할 수 있다.
- 증가 후 다시 조회한 실제 상태로 `기존`/`추가됨`을 비교한다. 기존 메시지는 재분배되지 않는다.
- 내부 토픽(`__` 접두사)은 상세 조회만 지원한다.
- 실행 명령과 원본 결과는 같은 패널 아래 Admin 터미널에서 확인한다.
